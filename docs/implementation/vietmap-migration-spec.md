## §4. Bất biến cứng (hard invariants)

**Phải giữ:**

1. Shape `TravelRoute`, shape `travelLegSchema`, 6 reason code, Prisma schema — không đổi.
2. `CAR → car`, `MOTORCYCLE → motorcycle`. Không thay profile khi lỗi.
3. Timeout ≤ 10 giây, không retry, `redirect: "error"`, `cache: "no-store"`, giới hạn byte response.
4. Fail-closed: mọi lỗi ⇒ `INSUFFICIENT_DATA`, không suy đoán thời gian/distance.
5. Chỉ adapter biết VietMap. Business layer chỉ gọi `getTravelRoute()` / `requestVietmapRoute()`.
6. Routing key không được xuất hiện trong: bundle client, log, `AppError`, response API, URL hiển thị.
7. Route geometry không hiển thị trên MapLibre (quyết định cũ vẫn hiệu lực).

**Không được làm:**

8. Không `toLocaleString` cho số trong query (dấu phẩy thập phân phá query).
9. Không return route đã cache khi breaker đang mở.
10. Không đổi `planner-engine`, `planner-validator`, `planner-candidates`, `planner-registry`, `trip-validation.ts`, `visit-constraints.ts`, `travel-time.ts`, US-35/36/37.
11. Không xoá tài liệu bằng chứng lịch sử trong `docs/implementation/*evidence*`.
12. Không thêm fallback sang Stadia/Google dù chỉ để test.

## §5. Dữ kiện nhà cung cấp đã kiểm chứng bằng probe thật (2026-10-23)

### 5.1. Basemap (tilemap)

```
https://maps.vietmap.vn/maps/styles/tm/style.json?apikey={key}   # light  (D3)
https://maps.vietmap.vn/maps/styles/dm/style.json?apikey={key}   # dark   (D3)
```

Kết quả probe thực tế:

| Kiểm tra | Kết quả |
| --- | --- |
| `GET style.json?apikey=<key sai>` | **HTTP 200**, trả style đầy đủ (không phân biệt key đúng/sai) |
| Style nhúng key vào tile URL | Có: `.../maps/tiles/vlc-20261015/{z}/{x}/{y}.pbf?apikey=<key>` |
| `GET .../tiles/.../10/814/463.pbf` không key / key sai | **HTTP 401** |
| `sources.*.attribution` | **Không có** ⇒ phải tự thêm `© VIETMAP` |
| `sources.openmaptiles.maxzoom` | `15` (khớp `maxZoom: 15` đang dùng) |

**Hệ quả:** không còn chế độ keyless. Key sai ⇒ bản đồ trắng chứ không báo lỗi rõ, vì style 200 còn tile 401. Repo đã có fallback `map.on("error")` → UI "Bản đồ chưa khả dụng" + danh sách vẫn dùng được; **giữ nguyên**, không thêm retry.

### 5.2. Routing (Route v4)

```
GET https://maps.vietmap.vn/api/route/v4
    ?apikey={key}
    &point={lat},{lng}
    &point={lat},{lng}
    &vehicle=car|motorcycle
    &points_encoded=true|false
```

| Field | Ý nghĩa thực tế |
| --- | --- |
| HTTP status | **200 kể cả khi lỗi nghiệp vụ** |
| `code` | `OK` / `ZERO_RESULTS` / `OVER_DAILY_LIMIT` / `INVALID_REQUEST` / `MAX_POINTS_EXCEED` / `ERROR_UNKNOWN` |
| `paths[0].distance` | **mét** |
| `paths[0].time` | **mili-giây** |
| `paths[0].points` | polyline5 nếu `points_encoded=true`; mảng toạ độ nếu `false` |
| `paths[0].bbox` | `[minLon, minLat, maxLon, maxLat]` |
| Khi lỗi | Không có `paths` khi `code !== "OK"` |

**Mâu thuẫn tài liệu:** trang Route v4 ghi thứ tự toạ độ `[lat,lng]` khi `points_encoded=false`, còn file `routing.txt` chính thức ghi `[lon,lat]`. ⇒ **Không tin docs**, chuẩn hoá runtime (§7.2.5).

**Khác Stadia:** Route v4 dùng `apikey` trên query string (Stadia dùng header `Authorization: Stadia-Auth …`), polyline **5** (Stadia polyline **6**), distance **mét** (Stadia km), time **ms** (Stadia giây).

### 5.3. Hạn mức

- 60.000 transaction miễn phí.
- Routing: `⌊points/5⌋ + 1` ⇒ leg 2 điểm = **1 transaction**; 27 cặp = **27 transaction/lần lập lịch**.
- Basemap: **25 tile = 1 transaction**.
- Có giới hạn ngày ⇒ `OVER_DAILY_LIMIT` trả HTTP 200 nhưng không có `paths`.
- Key tilemap: thiết kế để nhúng client, **bắt buộc** khai báo referer.
- Key routing: tài liệu VietMap ghi rõ "tuyệt đối không để lộ ở frontend".

## §7. Thiết kế đích

### 7.1. Basemap

`apps/web/src/modules/map/map-config.ts` thay bằng:

```ts
const TILE_KEY = process.env.NEXT_PUBLIC_VIETMAP_MAP_KEY;
const withKey = (style: string) => TILE_KEY
  ? `https://maps.vietmap.vn/maps/styles/${style}/style.json?apikey=${encodeURIComponent(TILE_KEY)}`
  : `https://maps.vietmap.vn/maps/styles/${style}/style.json`;

export const vietmapStyles = { light: withKey("tm"), dark: withKey("dm") } as const;
export function mapStyle(theme: string | undefined) { return theme === "dark" ? vietmapStyles.dark : vietmapStyles.light; }
```

- Thiếu key ⇒ URL không có `apikey` ⇒ tile 401 ⇒ UI fallback. **Không throw**, không chặn render.
- `mapStyle` giữ nguyên chữ ký ⇒ 4 component gọi nó không phải sửa.
- Giữ `verifyMapWorkerAssets` / `loadMapLibre` nguyên vẹn.

Attribution — thêm `customAttribution: "© VIETMAP"` vào **cả 3** constructor (§6.2):

```ts
attributionControl: { compact: true, customAttribution: "© VIETMAP" }
```

### 7.2. Adapter `apps/web/src/modules/trip-validation/vietmap-route.ts`

**Chữ ký xuất khẩu phải giữ tương thích 1-1 với file cũ** để 5 importer production + 2 type import chỉ cần đổi đường dẫn:

```ts
import "server-only";
import { isValidMapCoordinate, type MapCoordinate, type RouteGeometry } from "../map/map-model";
import { assertSupportedTransportValue } from "../trip-requirement/trip-transport-policy";
import { checkTravelTime, type VisitPair } from "./travel-time";

export type TravelRoute =
  | { kind: "ok"; durationSeconds: number; distanceMeters?: number; geometry?: RouteGeometry }
  | { kind: "unavailable" };

type RouteInput = {
  origin: MapCoordinate | null | undefined;
  destination: MapCoordinate | null | undefined;
  vehicle: unknown;
};

type RouteOptions = {
  apiKey?: () => string | undefined;
  fetcher?: typeof fetch;
  timeoutMs?: number;
  signal?: AbortSignal;
  now?: () => number;            // NEW: clock tiêm được, phục vụ test breaker
};

export type VietmapRouteFailure =
  | "NOT_CONFIGURED" | "TIMEOUT" | "UNAVAILABLE"
  | "UNSUPPORTED_MODE" | "NO_ROUTE" | "INVALID_RESPONSE";

export type VietmapRouteResult =
  | Exclude<TravelRoute, { kind: "unavailable" }>
  | { kind: "unavailable"; reason: VietmapRouteFailure };

export const MAX_VIETMAP_RESPONSE_BYTES = 512 * 1024;
export const VIETMAP_ROUTE_URL = "https://maps.vietmap.vn/api/route/v4";

export function toVietmapVehicle(vehicle: unknown): "car" | "motorcycle";
export async function requestVietmapRoute(input: RouteInput, options?: RouteOptions): Promise<VietmapRouteResult>;
export async function getTravelRoute(input: RouteInput, options?: RouteOptions): Promise<TravelRoute>;
export async function checkTravelLeg(input: RouteInput & VisitPair, options?: RouteOptions): Promise<{ route: TravelRoute; check: ReturnType<typeof checkTravelTime> }>;
export function resetVietmapBreakerForTests(): void;   // chỉ dùng trong test
```

#### 7.2.1. Thứ tự kiểm tra (giữ đúng như code cũ)

1. `toVietmapVehicle(input.vehicle)` — throw nếu transport không hỗ trợ ⇒ `UNSUPPORTED_MODE`. Hàm này gọi `assertSupportedTransportValue`, nên hành vi 422 của caller giữ nguyên.
2. `isValidMapCoordinate(origin)` và `destination` — sai ⇒ `INVALID_RESPONSE` (**đây là toạ độ đầu vào**).
3. `timeoutMs` mặc định `10_000`; phải là số nguyên trong `[1, 10_000]`, nếu không thì `throw new RangeError("Invalid routing timeout")` (giữ y hành vi cũ).
4. Breaker: nếu đang mở ⇒ trả `UNAVAILABLE` **ngay**, không gọi mạng.
5. Key: `(options.apiKey ?? (() => process.env.VIETMAP_ROUTING_API_KEY))()`; rỗng ⇒ `NOT_CONFIGURED`.
6. Gọi HTTP, đọc body có giới hạn byte, parse, map.

#### 7.2.2. Request

```ts
const url = `${VIETMAP_ROUTE_URL}?apikey=${encodeURIComponent(key)}` +
  `&point=${origin.latitude},${origin.longitude}` +
  `&point=${destination.latitude},${destination.longitude}` +
  `&vehicle=${vehicle}&points_encoded=false`;
```

- Dùng template thô cho số. **Cấm** `toLocaleString`.
- `method: "GET"`, `redirect: "error"`, `cache: "no-store"`, `signal: controller.signal`.
- Không set header auth (key nằm trong query).
- Không truyền `time` (D5).
- **Không log `url`** ở bất kỳ đâu, kể cả trong nhánh lỗi.

#### 7.2.3. Đọc body

Giữ nguyên kỹ thuật của file cũ: `response.body.getReader()`, cộng dồn `byteLength`, vượt `MAX_VIETMAP_RESPONSE_BYTES` ⇒ `cancel()` + `INVALID_RESPONSE`; `TextDecoder("utf-8", { fatal: true })`; abort giữa chừng ⇒ `TIMEOUT`; `Promise.race([request(), cancelled])` + `clearTimeout` trong `finally`.

#### 7.2.4. Map `code` → reason (fail-closed)

| Điều kiện | Reason | Ghi chú |
| --- | --- | --- |
| không có key | `NOT_CONFIGURED` | |
| vehicle không hỗ trợ | `UNSUPPORTED_MODE` | |
| abort/timeout | `TIMEOUT` | kể cả abort từ caller |
| HTTP ≠ 2xx | `UNAVAILABLE` | cancel body trước khi return |
| `code === "ZERO_RESULTS"` | `NO_ROUTE` | **không** trip breaker |
| `code === "OVER_DAILY_LIMIT"` | `UNAVAILABLE` | **trip breaker** 15 phút |
| `code === "INVALID_REQUEST"` / `"MAX_POINTS_EXCEED"` | `INVALID_RESPONSE` | lỗi do mình gửi sai |
| `code === "ERROR_UNKNOWN"` | `UNAVAILABLE` | |
| `code === "OK"` nhưng thiếu/sai `paths[0]` | `INVALID_RESPONSE` | |
| `code` khác/lạ/không có | `INVALID_RESPONSE` | không đoán |
| JSON hỏng / body quá lớn | `INVALID_RESPONSE` | |
| fetch throw | `UNAVAILABLE` | |

#### 7.2.5. Chuẩn hoá dữ liệu

```ts
const path = payload.paths?.[0];
const durationSeconds = typeof path?.time === "number" && Number.isFinite(path.time) && path.time >= 0
  ? path.time / 1000 : undefined;                     // ms → s  (bắt buộc chia 1000)
const distanceMeters = typeof path?.distance === "number" && Number.isFinite(path.distance) && path.distance >= 0
  ? path.distance : undefined;                        // đã là mét, KHÔNG nhân 1000
```

- `durationSeconds` bắt buộc có và `<= 604800`; `distanceMeters` bắt buộc có và `<= 10_000_000` (khớp `travelLegSchema`). Thiếu/ngoài biên ⇒ `INVALID_RESPONSE`.
- Geometry là **best-effort, không được làm hỏng route**:
  - `points_encoded=false` trả mảng `[a, b]`.
  - Thử đọc là `[lng, lat]`; nếu không qua `isValidMapCoordinate` hoặc nằm ngoài hộp Việt Nam (`lat 8…24`, `lng 102…110`) thì thử đảo `[lat, lng]`.
  - Cả hai đều sai ⇒ **bỏ geometry**, vẫn trả `ok` với duration/distance.
  - Chỉ trả `geometry` khi có ≥ 2 điểm hợp lệ.

> **Làm rõ so với bản kế hoạch trước:** bảng lỗi cũ ghi "toạ độ sai → `INVALID_RESPONSE`". Điều đó áp dụng cho **toạ độ đầu vào** (origin/destination). Toạ độ trong **response geometry** không được phép làm hỏng một leg có duration/distance hợp lệ, vì geometry không được render ở đâu cả.

#### 7.2.6. Breaker

```ts
const BREAKER_TTL_MS = 15 * 60_000;
let breakerOpenUntil = 0;
export function resetVietmapBreakerForTests() { breakerOpenUntil = 0; }

// trong requestVietmapRoute, TRƯỚC khi gọi mạng:
const now = options.now ?? Date.now;
if (breakerOpenUntil > now()) return { kind: "unavailable", reason: "UNAVAILABLE" };

// sau khi đọc code:
if (code === "OVER_DAILY_LIMIT") breakerOpenUntil = now() + BREAKER_TTL_MS;
```

Ràng buộc:
- Chỉ `OVER_DAILY_LIMIT` được trip. `ZERO_RESULTS`, `UNAVAILABLE` do mạng, `TIMEOUT` **không** trip.
- Không cache route, không trả route cũ khi breaker mở.
- Breaker nằm trong `requestVietmapRoute` ⇒ bảo vệ mọi caller (planner, save, edit, in-trip).
- Giới hạn đã biết: trên serverless breaker chỉ đúng trong 1 instance. Chấp nhận (D13–D15), ghi vào ADR-19/US-40.

#### 7.2.7. `getTravelRoute` và `checkTravelLeg`

Giữ y hành vi cũ:

```ts
export async function getTravelRoute(input, options = {}) {
  toVietmapVehicle(input.vehicle);          // caller cũ dựa vào throw này cho 422
  const result = await requestVietmapRoute(input, options);
  return result.kind === "ok" ? result : { kind: "unavailable" };
}
export async function checkTravelLeg(input, options = {}) {
  const route = await getTravelRoute(input, options);
  return { route, check: checkTravelTime(input, route) };
}
```

## §14. Đoạn dùng cho báo cáo / slide (D17)

**Trước → Sau**

```
TRƯỚC                                      SAU
MapLibre ─ Stadia Alidade style            MapLibre ─ VietMap vector tile (tm/dm)
  └ domain auth, không key                   └ publishable key + referer whitelist
                                            + attribution © VIETMAP

Server ─ Stadia Standard Routing            Server ─ VietMap Route v4
  auto / motorcycle                            car / motorcycle
  POST + header auth                            GET + apikey (query)
  polyline6, km                                 polyline5, mét + mili-giây
  provider "STADIA_MAPS"                        provider "VIETMAP"
```

**Ba lý do đổi provider**

1. **Dữ liệu đúng đối tượng:** VietMap xây dựng dữ liệu đường bộ Việt Nam tới cấp thôn/ấp, có profile `motorcycle` riêng; đường đèo Hà Giang và quy định xe máy không được mô hình hoá đầy đủ trên dữ liệu OSM toàn cầu của Stadia.
2. **Sửa một lỗi thật:** bản đồ Stadia ở môi trường production trả tile `401` do ràng buộc domain; sau khi đổi, tile trả `200` và có bằng chứng chụp màn hình.
3. **Kiến trúc không đổi:** chỉ thay adapter sau `getTravelRoute()`; Constraint Validator, In-trip và cơ chế lưu chuyến đi giữ nguyên — chứng minh thiết kế tách provider có tác dụng.
